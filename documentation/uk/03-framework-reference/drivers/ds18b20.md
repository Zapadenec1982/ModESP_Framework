# `ds18b20` — Dallas OneWire датчик температури

> 📖 **In English:** [documentation/en/03-framework-reference/drivers/ds18b20.md](../../../en/03-framework-reference/drivers/ds18b20.md)

DS18B20 — 1-Wire цифровий датчик температури (Dallas/Maxim, тепер ADI).
Кожен датчик має унікальну 64-bit ROM-адресу, тому багато датчиків
можуть сидіти на одній OneWire шині і addressed individually. Діапазон
-55…+125 °C, resolution configurable 9-12 bits.

Driver registers як `sensor` з `hardware_type: onewire_bus` і
`requires_address: true` — bindings must include ROM address
(наприклад `"28-3c01a8...."`). `multiple_per_bus: true` дозволяє багатьом
датчикам share одну bound bus.

REQUIRES: ESP-IDF OneWire driver, `modesp_hal`.

## Bindings

```json
{
  "id": "freezer_temp",
  "driver": "ds18b20",
  "hardware_id": "ds18b20_freezer",
  "role": "freezer_temp",
  "bus": "onewire_bus_1",
  "address": "28-3c01a801a2b3"
}
```

`role` — abstract sensor role consumed by Equipment Manager
(наприклад `equipment.freezer_temp`). `bus` references board-defined
OneWire master. `address` — ROM (hex із dashes optional).

## Settings (persisted)

| Key | Type | Default | Notes |
|---|---|---|---|
| `read_interval_ms` | int 500-60000 | 1000 | Інтервал опитування. |
| `offset` | float -5…+5 °C | 0.0 | Корекція показань (calibration). |
| `resolution` | int 9-12 bits | 12 | Trade-off: 12-bit ≈ 750 ms conversion, 9-bit ≈ 94 ms. |

Settings persist через PersistService під namespace `drv:<binding_id>`.

## Provides

`{"type": "float", "unit": "°C", "range": [-55, 125]}` — publishes до
`equipment.<role>` через Equipment Manager.

NaN publishes якщо conversion fails (CRC mismatch, sensor disconnected).

## Discovery

Driver supports OneWire bus scanning:

```
POST /api/drivers/ds18b20/scan
{"bus": "onewire_bus_1"}
```

Returns array з `{address, temperature, parasitic}` records. Inline
temperature reading допомагає identify який саме physical sensor is
which (briefly warm one up із finger).

WebUI exposes "Scan OneWire bus" button на driver settings page
яка assigns scanned sensors до roles за кілька кліків.

## Common pitfalls

**Power glitches → CRC errors:** OneWire sensitive to long wires
without 4.7 kΩ pull-up. Use shorter buses або add terminator. Driver
retries 3× на CRC failure, then publishes NaN.

**Parasitic mode confusion:** Driver auto-detects parasitic power. Якщо
mix parasitic + powered sensors на одній bus, force `parasitic=true`
через board.json (повільніше conversion але consistent).

**Long conversion at 12-bit:** Не poll швидше ~1 Hz at 12-bit
resolution. Driver internally serialises conversions на shared buses.

## UI surface

Driver manifest declares per-binding settings card "DS18B20:
{{hardware_id}}" з number_input (interval), slider (offset), і select
(resolution). Visible на page "Налаштування датчиків" (service access).

## Чому це good first driver to read

- Demonstrates address-required pattern.
- Demonstrates bus-shared pattern (`multiple_per_bus`).
- Demonstrates discovery з scan endpoint.
- Demonstrates persistence через PersistService.
- ~200 LOC implementation — readable за один присід.
