# ADR-0007: Обов'язкові таймаути на кожну фазу

> 📖 **In English:** [documentation/en/03-framework-reference/scenario-engine/adr/0007-mandatory-phase-timeouts.md](../../../../en/03-framework-reference/scenario-engine/adr/0007-mandatory-phase-timeouts.md)

**Статус:** заглушка. Повністю буде написано на Кроці 8 (правила валідації modr_loader).

## Стислий виклад рішення

Кожна фаза МУСИТЬ мати таймаут — або явне значення `phase.timeout_ms`, або fallback до `header.default_phase_timeout_ms` (обов'язкове у заголовку сценарію). Рушій синтезує неявний перехід до `$abort`, якщо жоден явний перехід за часом не спрацював раніше.

**Жодних «нескінченних фаз».** Автор рецепта може встановити дуже великі значення (наприклад, 24 години), але обов'язкова межа існує завжди.

## Розглянуті альтернативи

- **Опціональні таймаути:** відхилено — універсальні у PLC-секвенсерах (ISA-88 явно вказує «phase failure timeout»). Без межі рецепт може зависнути назавжди.
- **Лише один таймаут на весь сценарій:** відхилено — занадто грубо; таймаут на рівні фази дозволяє специфічну для фази безпеку.
- **Таймаут у окремому файлі «safety contract»:** відхилено — over-engineering; вбудовування безпосередньо у `.modr` простіше.

## Наслідки

- Завантажувач валідовує наявність таймауту (або доступність fallback) — помилка компіляції, якщо відсутнє.
- Автори рецептів не можуть випадково створити фази, що зависають назавжди.
- Синтезується неявний перехід `$abort` — страхувальна сітка.
- Усі рецепти мають передбачуваний максимальний час виконання (сума таймаутів фаз + верхня межа scenario_timeout_max_ms).
