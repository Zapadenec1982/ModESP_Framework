# `ntc` — термістор NTC на каналі ADC

> 📖 **In English:** [documentation/en/03-framework-reference/drivers/ntc.md](../../../en/03-framework-reference/drivers/ntc.md)

Термістор NTC через канал ADC ESP32 з рівнянням за B-параметром. Дешевий, простий, поширений у холодильному обладнанні та HVAC, де точності ±0,5 °C достатньо. Діапазон зазвичай -40…+125 °C залежно від вибору резистора і термістора.

Драйвер реєструється як `sensor` з `hardware_type: adc_channel`, надає capability `temperature` і має `requires_address: false`. Один сенсор на прив'язаний канал ADC. Роль прив'язується за capability, а не за драйвером (R0.1 / R3.1) — модуль просить `temperature`, не знаючи, хто її дає (ntc / ds18b20 / BLE-канал).

ВИМАГАЄ: драйвер ADC з ESP-IDF, `modesp_hal`.

## Прив'язки

```json
{
  "id": "ambient",
  "driver": "ntc",
  "hardware_id": "adc_1",
  "role": "ambient_temp"
}
```

`role` оголошує здатність (`capability: temperature`), а не драйвер — Equipment Manager резолвить її за роллю (наприклад, `equipment.ambient_temp`), джерело замінне (R0.1). `hardware_id` посилається на визначений у платі канал ADC (`adc_channels[].id` у board.json, зі ступенем послаблення та розрядністю) — драйвер резолвить його через `find_adc_channel`. Драйвер не конфігурує сам ADC — це відповідальність плати.

## Налаштування (за замовчуванням не зберігаються — налаштуйте маніфест)

| Ключ | Тип | За замовчуванням | Примітки |
|---|---|---|---|
| `beta` | int 2000-5000 | 3950 | B-коефіцієнт термістора. |
| `r_series` | int 1k-100kΩ | 10000 | Послідовний резистор (підтяжка). |
| `r_nominal` | int 1k-100kΩ | 10000 | Опір NTC за 25 °C. |
| `read_interval_ms` | int 100-60000 | 1000 | Інтервал опитування. |
| `offset` | float -5…+5 °C | 0.0 | Калібрувальна корекція. |

Більшість NTC постачаються зі значеннями B і R25 з даташита. Поширені: B = 3950, R25 = 10 кΩ.

## Надає

`{"capability": "temperature", "type": "float", "unit": "°C", "range": [-40, 125]}` — публікується в `equipment.<role>`.

Якщо показання ADC у рейках (raw < 50 або > 4045 → сенсор обірваний або у короткому замиканні) чи температура поза діапазоном, драйвер пропускає оновлення й тримає останнє валідне значення; `read()` повертає `false`, поки жодного валідного показання не було. Після 5 послідовних помилок сенсор позначається нездоровим (`is_healthy()` = `false`).

## Рівняння за B-параметром

Стандартна спрощена форма Стейнхарта:

```
1/T = 1/T0 + (1/B) * ln(R / R0)
T   = T - 273.15  (Цельсій)
```

Де `R` — виміряний опір NTC, обчислений з напруги ADC і послідовного резистора у дільнику напруги.

Драйвер застосовує формулу на кожній вибірці. Без табличного пошуку, без інтерполяції. Обчислювальна вартість ~5 мкс.

## Виявлення

NTC не має виявлення — нема чого сканувати. Прив'язки оголошуються вручну.

## Типові помилки

**Неправильний напрямок дільника:** типова схема ставить NTC до GND і послідовний резистор до Vcc. Драйвер припускає саме це. Якщо ваша схема інвертована, поміняйте у обладнанні або перевизначте знак `beta` (просунутий варіант).

**Нелінійність ADC:** ADC ESP32 має погану лінійність біля рейок. Виберіть `r_series` так, щоб напруга NTC потрапляла у середні 60% діапазону ADC при типовій робочій температурі.

**Саморозігрів:** при опорі NTC <1 кΩ і живленні 3,3 В струм перевищує 3 мА — саморозігрів стає значущим. Використовуйте NTC 10 кΩ або вищий послідовний резистор.

**Дрейф B-коефіцієнта:** B — це логарифмічна апроксимація, яка втрачає точність далеко від 25 °C (>40 °C). Для широкого діапазону розгляньте DS18B20.

## Інтерфейс користувача

Маніфест, що постачається, не оголошує карток UI (лаконічний маніфест). Додайте картку налаштувань у своєму форку, якщо вашим операторам потрібно налаштовувати B у польових умовах.

## Чому це гарний драйвер для читання після `ds18b20`

- Контраст із цифровим сенсором: NTC потребує математики, обізнаності щодо конфігурації ADC.
- Демонструє випадок без адреси (`requires_address: false`).
- Демонструє випадок без виявлення.
- Демонструє налаштування, що не зберігаються (значення за замовчуванням у маніфесті, не у NVS).
