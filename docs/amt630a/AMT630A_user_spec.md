# AMT630A — специфікація драйвера під ESP32 (керування по I²C)

> Джерело: надано користувачем (зведення Arkmicro Spec V1.1 + повний реверс Martin Korth / no$x51 + Fizik `AMT630.h`). Канонічна довідка для розробки ModESP-драйвера AMT630A.

**Призначення:** замінити окремий OSD-чіп AT7456E на вбудований OSD-рушій AMT630A, керуючи дисплейним SoC ззовні по I²C з ESP32. Документ зводить офіційний даташит (Arkmicro V1.1) і повний реверс Martin Korth (no$x51, problemkaputt.de) у придатну для роботи карту регістрів.

**Контекст KOZHAN:** AMT630A на платі ZCD-630A-4.3D+SPI вже виводить відео на LCD 4.3″. Мета — використати його OSD (текст/графіка/кирилиця, 5 вікон), 3 CVBS-входи для відображення діапазонів, і прибрати AT7456E з проєкту. **Детекція лишається на ESP32 (сирий CVBS, ADC1) — AMT630A для відображення, не для детекції слабких сигналів** (у нього апаратний sync-lock).

## 1. Що таке AMT630A і два шляхи керування

AMT630A — це **8051 (80C31/80C52) @ 6.75 МГц з прошивкою на зовнішньому SPI-flash** (256–512 КБ, прошивка <48 КБ) плюс апаратний video-decoder + scaler + TCON + OSD-рушій. Твоя SPI-маркована плата = AMT630A + цей flash. Чіп **автономний**: сам вантажить прошивку і працює.

Керувати ним можна двома способами:

| Шлях | Що дає | Складність | Ризик |
|------|--------|-----------|-------|
| **A. I²C ззовні (рекомендовано)** | Зміна OSD, вибору входу, яскравості — поверх працюючої прошивки | Низька | Безпечно |
| **B. Дамп + реплейс прошивки** | Повний контроль (vsync-IRQ, FLASH-to-FONT DMA) | Висока (реверс 8051) | DANGER-біти |

Цей документ описує **Шлях A**. Він повторює підхід Fizik (`AMT630.h`), але з повною картою регістрів замість лише цифр+латиниці.

### Критичне розмежування: що доступне по I²C, а що ні

AMT630A має два адресні простори. Розрізняй їх:

- **XRAM I/O-порти `FBxx–FFxx`** — доступні **і** внутрішньому MCU (через `MOVX`), **і** ззовні через **I²C slave**. Сюди входить **усе практичне**: OSD-вікна, текст, шрифт, вибір CVBS, яскравість, підсвітка PWM, палітра.
- **CPU SFR `80h–FFh`** (напр. `SFR 91h` vsync-прапор, `SFR C6h` memory_system) — **тільки внутрішній MCU**. **Недоступні по I²C.**

Наслідок: по I²C ти **не** прочитаєш vsync-прапор `SFR 91h.bit7` і **не** запустиш FLASH-to-FONT DMA (потребує `SFR C6h.bit3`). Але це й **не потрібно** — мерехтіння на AMT630A вирішується інакше (розділ 9), а кирилицю вантажиш ручними записами у FONT RAM (розділ 8).

## 2. Карта банків: MCU-адреса ↔ I²C-адреса

Це «розетський камінь» документа. Кожен банк MCU `Fxxx` = окрема I²C-адреса; **низький байт MCU-адреси = номер регістра в I²C-транзакції**.

| MCU-банк | I²C 8-біт (W) | I²C 7-біт | Підсистема |
|----------|--------------|-----------|-----------|
| `FBxx` | `0xB6` | **`0x5B`** | **OSD** (вікна, BGMAP, FONT, палітра) |
| `FCxx` | `0xB8` | `0x5C` | Tcon / Scaler / LCD-тайминг (50/60 Гц) |
| `FDxx` | `0xB0` | **`0x58`** | Global, **PWM (підсвітка)**, ADC, SPI-flash, PLL, PIN |
| `FExx` | `0xB2` | **`0x59`** | **AV-декодер / вибір CVBS-входу** |
| `FFxx` | `0xB4` | `0x5A` | Video-process, GAMMA, **яскравість/контраст** |

(Збігається з Fizik: `0x58`=Global, `0x59`=AV, `0x5B`=OSD, `0x5C`=LCD. У Fizik LCD названо `0x58` помилково — насправді `0x58` це Global, а Tcon/LCD = `0x5C`.)

### Формат I²C-транзакції

```c
// Запис одного регістра XRAM Fxxnn = value:
//   device = I²C-7-біт банку (0x58..0x5C)
//   reg    = низький байт nn
//   приклад: FB05h = 0x01  →  пишемо у 0x5B, регістр 0x05, значення 0x01
void amt_w(uint8_t dev7, uint8_t reg, uint8_t val) {
    i2c_master_start();
    i2c_master_write_byte((dev7 << 1) | 0, true);   // device + WRITE
    i2c_master_write_byte(reg, true);                // register (low byte)
    i2c_master_write_byte(val, true);                // data
    i2c_master_stop();
}
// Читання (для статусних регістрів, напр. детект сигналу):
uint8_t amt_r(uint8_t dev7, uint8_t reg) {
    // write reg pointer, then repeated-start read 1 byte
    ...
}
```

> **Застереження:** даташит дає обидві адреси (I²C і MCU) для кожного банку, тож відповідність надійна. Але реверс Korth робився з боку MCU. Якщо якийсь регістр поводиться інакше по I²C — звір на бенчі. Практичні регістри (OSD/AV/яскравість/PWM) у Fizik підтверджено працюють по I²C.

## 3. Вибір CVBS-входу (3 входи) — банк `FExx` / I²C `0x59`

AMT630A має **3 фізичні CVBS-входи** (CVBS1/2/3) з внутрішнім мукером. На більшості плат CVBS2 заземлений (екран між двома іншими), у GUI «AV2»=CVBS3. Це може замінити CD4052 **на боці відображення**.

**Послідовність перемикання входу** (строго в цьому порядку):
```
1. Скинути FED7h (video_on_off) bit3,4         → 0
2. Змінити FED8h (input_select_0) bit6,7
3. Встановити FED7h (video_on_off) bit3,4      → 3
4. Змінити FEDCh (input_select_1) bit4,5
```

**Значення (новіша прошивка):**

| Вхід | `FED7h` bit3-4 | `FED8h` bit6-7 | `FEDCh` bit4-5 |
|------|---------------|----------------|----------------|
| CVBS1 (AV1) | 0 → 3 | 2 | 0 |
| CVBS3 (AV3) | 0 → 3 | 0 | 2 |

По I²C: пишеш у `0x59`, регістри `0xD7`, `0xD8`, `0xDC`.

**Детект наявності сигналу** (читання, `0x59`):

| Регістр | Біт | Значення |
|---------|-----|----------|
| `FE2Ah` | bit4 | сигнал на **вибраному** вході |
| `FE2Ah` | bit6 | сигнал на **невибраному** вході |
| `FE26h` | bit1,2 | video DETECT (часто вживаний прошивкою) |
| `FE28h` | bit2 | PAL/NTSC (50/60 Гц) |

> Це апаратний детект **для відображення**, не для детекції слабких дронів. Для детекції — твій ADC1-тракт на ESP32.

## 4. OSD: архітектура

OSD-рушій складається з трьох областей пам'яті:

| Область | Розмір | Призначення |
|---------|--------|-------------|
| **BGMAP RAM** | 200h записів | «екран»: кожен запис = 10-біт № символу + 7-біт атрибут (колір) |
| **FONT RAM** | 1000h слів (8 КБ) | завантажуваний шрифт (сюди — **кирилиця/графіка**) |
| **FONT ROM** | 418 символів 16×22 1bpp | вбудований: цифри, лат. великі, **трохи кирилиці** (02Ch–04Ch), символи, бари батареї/сигналу |

**Номери символів (для BGMAP):**

| Діапазон | Що |
|----------|-----|
| `000h..1BFh` | ROM-шрифт (фіксований). `000h`=пробіл, `001h–00Ah`="0–9", `00Bh–024h`="A–Z", `02Ch–04Ch`=кирилиця (нетиповий порядок), `137h–13Bh`=символи батареї |
| `1C0h..xxxh` | **кастомний RAM-шрифт** (твоя кирилиця, 1bpp) |
| далі | RAM-шрифт 4bpp (16-кольорова графіка) |

**5 вікон.** Кожне має розмір, позицію, BGMAP-адресу, масштаб. Вікно 0 — найвищий пріоритет, BGMAP-адреса фіксована (000h).

### Налаштування вікна 0 (банк `FBxx` / I²C `0x5B`)

| Регістр | Призначення |
|---------|-------------|
| `FB05h` | **enable-біти вікон** (bit0–4 = Window 0–4 on/off); bit7 = 4bpp bitmap |
| `FB76h` | розмір символу X у пікселях (1–24) |
| `FB77h` | розмір символу Y (1–32) |
| `FB07h` | ширина вікна 0 у символах (1–127) |
| `FB08h` | висота вікна 0 у символах (1–63) |
| `FB09h` | старші біти X/Y-позиції + BGMAP-addr msb |
| `FB0Ah` | X-позиція lsb (10 = крайня ліва) |
| `FB0Bh` | Y-позиція lsb (12 = крайня верхня) |
| `FB32h` | масштаб вікна 0 (×2/×3/×4/×5) |

## 5. Вивід тексту (BGMAP) — банк `FBxx` / I²C `0x5B`

Запис символу = адреса в BGMAP + номер символу + атрибут кольору.

**Регістри:**

| Регістр | Призначення |
|---------|-------------|
| `FB00h` | BGMAP-addr lsb (**авто-інкремент** при записі data!) |
| `FB0Dh` | BGMAP-addr msb (інкрементувати **вручну** при переповненні lsb) |
| `FB01h` | data lsb (молодші 8 біт № символу) — **запис сюди шле в VRAM** |
| `FB0Eh` | data msb (старші 2 біти № символу) — лише латчиться |
| `FB10h` | атрибут: bit0–2 = колір тексту (0=прозорий,1–6=палітра,7=чорний), bit4–6 = колір фону |

**Алгоритм запису рядка** (псевдокод під `amt_w`, dev=`0x5B`):
```c
// Вивести рядок text у позицію addr у BGMAP вікна
void osd_print(uint16_t bgmap_addr, const uint8_t *chars, int n,
               uint8_t text_color, uint8_t bg_color) {
    // 1. виставити стартову адресу
    amt_w(0x5B, 0x0D, (bgmap_addr >> 8) & 1);   // addr msb
    amt_w(0x5B, 0x00, bgmap_addr & 0xFF);        // addr lsb
    // 2. атрибут (можна один раз на рядок, якщо однаковий)
    amt_w(0x5B, 0x10, (text_color & 7) | ((bg_color & 7) << 4));
    // 3. символи: msb пишемо ОДИН раз, далі лише lsb (авто-інкремент addr)
    amt_w(0x5B, 0x0E, 0x00);                     // data msb (для кодів <256)
    for (int i = 0; i < n; i++)
        amt_w(0x5B, 0x01, chars[i]);             // data lsb → у VRAM, addr++
}
```

**Нюанси (з реверсу Korth):**
- `addr_lsb` авто-інкрементується **лише** при записі `data_lsb` (`FB01h`), переносу в `addr_msb` **немає** — стеж за переповненням 8-біт сам.
- При запису `data_lsb` у VRAM іде **і lsb, і msb**. Тому `data_msb` (`FB0Eh`) пиши лише коли старші біти змінюються; для кодів символів <256 виставив раз `0x00` і далі шлеш лише lsb.
- **Читання BGMAP/FONT неможливе** — назад регістри віддають лише останнє записане. Тримай тіньову копію в RAM ESP32, якщо треба знати стан.

**Приклад статус-рядка детектора:** `5800 A DET -72 BAT85` — це цифри+латиниця (ROM-шрифт, коди прямо доступні), виводиться без завантаження кастомного шрифту.

## 6. Палітра / кольори — банк `FBxx` / I²C `0x5B`

6 програмованих кольорів (1–6) + 2 фіксовані (0=прозорий/відео, 7=чорний).

| Регістр | Колір |
|---------|-------|
| `FB56h`/`FB57h` | колір 1 (msb=B, lsb=G/R) |
| `FB58h`/`FB59h` | колір 2 |
| `FB5Ah`/`FB5Bh` | колір 3 |
| `FB5Ch`/`FB5Dh` | колір 4 |
| `FB5Eh`/`FB5Fh` | колір 5 |
| `FB60h`/`FB61h` | колір 6 |

Формат 12-біт RGB (по 4 біти, реально 0–10 — значення 11–15 = той самий max):
```
lsb-байт: bit0-3 = Red(0..10),  bit4-7 = Green(0..10)
msb-байт: bit0-3 = Blue(0..10), bit4-7 = 0
```

**Напівпрозорість** (відео видно крізь OSD): `FB06h` bit6 (фон), bit7 (текст); рівень — `FB0Ch` bit0–2. Це дозволяє накласти статус-текст поверх живого відео дрона, не закриваючи картинку.

## 7. Кирилиця: завантаження шрифту в FONT RAM — банк `FBxx` / I²C `0x5B`

ROM має лише обмежену кирилицю (02Ch–04Ch, «нетиповий порядок»). Для повного україномовного меню вантаж **власні символи у FONT RAM** з номерами `1C0h+`.

**Регістри ручного запису шрифту:**

| Регістр | Призначення |
|---------|-------------|
| `FB02h` | font-addr lsb (12-біт адреса слова) |
| `FB0Fh` | font-addr msb |
| `FB03h` | font-data lsb (16-біт слово; bit0 = лівий піксель) |
| `FB04h` | font-data msb |

**Формат 1bpp-тайлу:** ширина округлюється до 16 біт (≤16px) або 24 біт (>16px). Кожен ряд — 16 пікселів: байт msb (пікселі 1–8) + lsb (9–16). Розмір тайлу = ширина × висота, округлено до кратного 16 біт.

**Алгоритм завантаження (з обходом glitch):**
```
1. ВИМКНУТИ всі вікна:   FB05h = 0x00      ← обов'язково! (інакше glitch при записі)
2. (пауза ~1 кадр; вимкнення діє з наступного кадру)
3. для кожного символу:
     виставити FB02h/FB0Fh = font-addr символу
     для кожного слова бітмапа:
        FB04h = data_msb;  FB03h = data_lsb   (data_lsb латчить обидва в VRAM)
4. УВІМКНУТИ вікна назад: FB05h = потрібні біти
```

> **Чому не DMA:** FLASH-to-FONT DMA швидший, але керується `SFR C6h.bit3` — це **CPU-SFR, недоступний по I²C**. Тому при зовнішньому керуванні — лише ручні записи (`FB02h/03h/04h`). `SFR C6h.bit3` для ручних записів **не працює** (Korth прямо це зазначає — він «псує» ручні записи), тому захист від glitch — саме **вимкнення вікон** (`FB05h=0`), не C6h.

Завантажуєш шрифт **один раз** при старті (з PROGMEM-таблиці в ESP32). Розмір FONT RAM = 8 КБ — вистачає на повний кириличний набір 16×22 з запасом.

## 8. Підсвітка PWM — економія енергії — банк `FDxx` / I²C `0x58`

**Велика знахідка Korth:** заводська прошивка тримає PWM0 (підсвітка) **завжди HIGH** → максимальна яскравість і марна витрата енергії. Перехід на duty 50% дає драматичну економію:

| Duty | Уся система | Лише підсвітка |
|------|-------------|----------------|
| 100% (HIGH) | 290 мА (1.45 Вт) | 234 мА (1.17 Вт) |
| **50%** | **65 мА (0.33 Вт)** | **9 мА (0.05 Вт)** |
| 0% (LOW) | 56 мА (0.28 Вт) | 0 мА |

**Регістри:**

| Регістр | Призначення |
|---------|-------------|
| `FD1Fh` | enable: bit0 = PWM0 (підсвітка) on |
| `FD20h`/`FD21h` | PWM0 total (період, у циклах 26 МГц) |
| `FD28h`/`FD29h` | PWM0 high (тривалість HIGH) |

**50% яскравість:** total = `0x1000`, high = `0x0800`.
```c
amt_w(0x58, 0x20, 0x00); amt_w(0x58, 0x21, 0x10);  // total = 0x1000
amt_w(0x58, 0x28, 0x00); amt_w(0x58, 0x29, 0x08);  // high  = 0x0800
amt_w(0x58, 0x1F, 0x01);                            // PWM0 enable
```

> Підсвітка **не працює при надто малих total** (напр. лишається off при total=0x0100).
> **Перевір на бенчі:** працює, якщо пін PWM0 вже в PWM-режимі. Якщо заводська прошивка тримає пін як «цифровий HIGH» (а не «PWM 100%»), перемикання режиму піна потребує `SFR MODE`-біти (CPU-only) — тоді економія доступна лише через реплейс прошивки. Якщо ж пін у PWM-режимі на 100% — запис duty по I²C спрацює одразу.

## 9. Мерехтіння OSD — чому на AMT630A його не буде

Твоя проблема мерехтіння була на **AT7456E** — окремому чіпі, де ти писав у display memory під час активного відео. На AMT630A це **не відтворюється так само**, бо:
- AMT630A — це **інтегрований** video+OSD SoC: апаратний OSD-рушій безперервно читає BGMAP/FONT і композитить поверх відео з власним таймингом. Ти не «малюєш під час кадру» — ти лише **оновлюєш дані**, які рушій підхоплює сам.
- Оновлення **тексту** (BGMAP) — атомарні по запису, безпечні.
- Єдине, що glitch-небезпечне — **запис шрифту (FONT RAM)** під час рендера; рішення вже описано (вимкнути вікна на час завантаження, розділ 7).

**Нюанс vsync по I²C:** прапор вертикального гасіння `SFR 91h.bit7` (set раз на кадр, IRQ 005Bh) — **CPU-SFR, недоступний по I²C**. Тобто синхронізувати записи по vsync ззовні не можна. Але це й не потрібно: для текстових оновлень BGMAP апаратна композиція AMT630A робить їх чистими без ручної vsync-синхронізації. Якщо колись знадобиться кадрова синхронність для важкої графіки — це аргумент за Шлях B (реплейс прошивки, де vsync-IRQ доступний).

## 10. Яскравість / контраст / насиченість — банк `FFxx` / I²C `0x5A`

| Регістр | Параметр | Medium |
|---------|----------|--------|
| `FFD3h` | контраст | `0x7E` |
| `FFD4h` | яскравість | `0x8E` |
| `FFD6h` | насиченість | `0x38` |
| `FFD5h` | tint (лише NTSC) | `0x00` |

> **BUG (Korth):** встановлення `FFD5h` bit7 ламає декодування кольору PAL, хоча tint має діяти лише на NTSC. Не чіпай bit7 tint.

## 11. Keypad ADC (опційно) — банк `FDxx` / I²C `0x58`

Якщо використовуєш кнопкову плату на ADC-каналі 0 (резисторна драбина):

| ADC-значення | Кнопка (3.5″) |
|--------------|---------------|
| ~`0x0564` | + (Up/Right), 1 кОм |
| ~`0x0804` | Menu, 2 кОм |
| ~`0x0B38` | − (Down/Left), 4.7 кОм |
| ~`0x0FF5` | нічого не натиснуто |

> На 4.3″-дисплеях + і − **поміняні місцями** (та сама плата змонтована навпаки). Читай ≥2 стабільні значення поспіль для дебаунсу.

## 12. DANGER-регістри — НЕ чіпати

З реверсу Korth, регістри, що **вішають/перезавантажують чіп**:

| Регістр | Небезпека | Доступ |
|---------|-----------|--------|
| `SFR C6h` bit0 | reboot при зміні | CPU (не по I²C) |
| `SFR C6h` bit7 | hang | CPU |
| `SFR D8h` bit5 | CPU у 21× повільніший | CPU |
| `FDD0h` | SPI transfer mode — flash-операції | **I²C — уникай!** |
| `FDDEh` bit6 | hang CPU | **I²C — уникай!** |
| `FDE0h` | crashes CPU | **I²C — уникай!** |
| `FD32h`/`FD33h` | SPI-flash піни | **I²C — уникай!** |
| `PCON` bit0-1 | halt/idle | CPU |

**Правило для Шляху A:** тримайся банків **OSD (`0x5B`)**, **AV (`0x59`)**, **яскравість (`0x5A`)**, і обережно **PWM-частини `0x58`** (`FD1Fh–FD29h`). **Не лізь** у SPI-flash область `0x58`/`FDD0h–FDE7h` — це для дампу прошивки (Шлях B), і там DANGER.

## 13. Послідовність запуску (Шлях A, мінімальна)

При зовнішньому керуванні прошивка AMT630A вже ініціалізувала чіп (декодер, PLL, LCD-тайминг). Тобі лишається:
```
1. Дочекатись, поки прошивка AMT630A стартувала (після power-on ~стабілізація).
2. (опц.) Підсвітка 50%:   FD20/21=0x1000, FD28/29=0x0800, FD1F=0x01   (dev 0x58)
3. Вибрати CVBS-вхід:       послідовність FED7→FED8→FED7→FEDC          (dev 0x59)
4. (раз) Завантажити кирилицю у FONT RAM 1C0h+ (вимкнути вікна на час)  (dev 0x5B)
5. Налаштувати вікно 0:     FB05/07/08/09/0A/0B, розмір символу FB76/77 (dev 0x5B)
6. Палітра:                 FB56..FB61 (кольори 1–6)                     (dev 0x5B)
7. Цикл: оновлювати статус-рядок через osd_print() при зміні даних      (dev 0x5B)
```

## 14. Підсумок і рекомендація під KOZHAN

- **AMT630A повністю заміняє AT7456E** і дає більше: 5 вікон, завантажуваний шрифт 16×22 (**кирилиця**), графіка, напівпрозорість, 3 CVBS-входи. **Прибери AT7456E** → вільний `CS_OSD=IO5`, нема AT7456E-мерехтіння, україномовне меню.
- **Керуй по I²C (Шлях A)** — безпечно, поверх працюючої прошивки. Уся практика (OSD/AV/яскравість/PWM) доступна через `FBxx–FFxx` → I²C `0x58–0x5C`.
- **Детекцію лиши на ESP32** (ADC1, сирий CVBS). AMT630A — для **відображення**.
- **Економія енергії:** PWM-підсвітка 50% → ~290→65 мА (перевір режим піна на бенчі).
- **Що перевірити на бенчі:** (1) чи всі OSD/AV-регістри відповідають по I²C як у Korth; (2) чи прошивка не перезаписує твої OSD-вікна (конфлікт); (3) чи пін PWM0 у PWM-режимі для регулювання яскравості; (4) точні значення `FED7/D8/DC` для перемикання входів на твоїй ревізії прошивки.

**Джерела:** Arkmicro AMT630A Specification V1.1; Martin Korth no$x51 reverse-engineering (problemkaputt.de/x51specs.htm); Fizik `AMT630.h` (підтверджений I²C-доступ 0x58/0x59/0x5B).
