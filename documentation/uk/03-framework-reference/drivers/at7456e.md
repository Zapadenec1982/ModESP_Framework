# `at7456e` — OSD-накладка на композитне відео (SPI)

> 📖 **In English:** [.../en/.../at7456e](../../../en/03-framework-reference/drivers/at7456e.md)

Дисплейний backend для чипа AT7456E (сумісний з MAX7456) — OSD-оверлей символів
поверх композитного (CVBS) відео. Драйвер надає здатність **`display`** через
семантичний шов `IDisplayPort` (див. [ADR-002](../../../../docs/display/ADR-002-display-architecture.md)) —
рідний брат `amt630a`. Модуль `display` штовхає у нього семантичні View
(`present_main`/`present_menu`/`present_notice`), а весь layout (скрол, курсор,
центрування, мапінг у гліфи NVM-шрифту) інкапсульований у драйвері.

**Здатність, не драйвер.** За [R0.1](../rules.md#r01--роль--здатність-capability-ніколи-не-драйвер)
дисплей — це здатність `display`, яку модуль споживає, не знаючи чипа. `display`
у системі — одинак, тож замість bindings.json backend обирається Kconfig-вибором
`choice` (див. [ADR-002 §2](../../../../docs/display/ADR-002-display-architecture.md), рішення «БЕЗ registry»).
Модуль `display` не має `#include` конкретного порту — він бере обраний
`IDisplayPort*` через DI.

> ⚠️ **Примітка:** піни цього драйвера читаються з **Kconfig**, а не з
> `board.json`. Це тимчасовий виняток (інші драйвери беруть периферію з board.json)
> до появи секції `spi_displays` у board.json (roadmap Phase 3). Доти драйвер
> компілюється, але прив'язати його через board.json/bindings.json **не можна**.

## Здатність і канали

| Поле | Значення |
|------|----------|
| `category` | `display` |
| `hardware_type` | `spi_display` |
| `transport` | `wired` |
| `provides.capability` | `display` |
| `provides.type` | `display` |

Здатність `display` **не має каналів** у сенсі sensor/actuator — драйвер не
публікує state-ключів у SharedState. Він споживає семантичні View від модуля
`display` і рендерить їх на екран. Порівняй із сенсорним `ble_xiaomi_th`, де один
пристрій дає кілька каналів (`temperature`/`humidity`/`battery`) — для `display`
такого поділу немає.

## Прив'язки

`display` — одинак, тож прив'язка йде **не через bindings.json**, а через
Kconfig-вибір backend та піни. У `idf.py menuconfig`:

1. Увімкнути драйвер: **ModESP Drivers → AT7456E** (`CONFIG_MODESP_DRIVER_AT7456E`).
2. Задати піни й відео-параметри в меню **AT7456E driver (pins/video)**.

Або напряму у `sdkconfig.defaults`:

```
CONFIG_MODESP_DRIVER_AT7456E=y
CONFIG_MODESP_DISPLAY_AT7456E_CS=5
CONFIG_MODESP_DISPLAY_AT7456E_MOSI=23
CONFIG_MODESP_DISPLAY_AT7456E_CLK=18
CONFIG_MODESP_DISPLAY_AT7456E_MISO=19
CONFIG_MODESP_DISPLAY_AT7456E_PAL=y
CONFIG_MODESP_DISPLAY_AT7456E_SYNC_AUTO=y
```

Реєстрація backend — одна точка у `drivers/at7456e/src/at7456e_port.cpp:134`:

```cpp
MODESP_REGISTER_DISPLAY(at7456e, &at7456e_factory)
```

Фабрика повертає singleton `At7456ePort` (zero-heap); `Binding`/`HAL` не
використовуються — backend обирається саме Kconfig-вибором, а не рядком board.json.

## Налаштування

Маніфест не має секції `settings` — усі параметри задаються через Kconfig
(`drivers/at7456e/Kconfig`):

| Kconfig | Опис | За замовчуванням |
|---------|------|------------------|
| `MODESP_DISPLAY_AT7456E_CS` | GPIO лінії CS | `5` |
| `MODESP_DISPLAY_AT7456E_MOSI` | GPIO лінії DATA/MOSI | `23` |
| `MODESP_DISPLAY_AT7456E_CLK` | GPIO лінії CLK | `18` |
| `MODESP_DISPLAY_AT7456E_MISO` | GPIO лінії MISO | `19` |
| `MODESP_DISPLAY_AT7456E_STD` | Відеостандарт: `PAL` (16 рядків) / `NTSC` (13 рядків) | `PAL` |
| `MODESP_DISPLAY_AT7456E_SYNC` | Джерело sync: `auto` / `internal` / `external` | `auto` |

Джерело sync: `internal` — власний sync (екран горить без вхідного відео);
`auto` — internal лише при втраті вхідного sync; `external` — тримати вхідний sync.

## Протокол і залізо

| Параметр | Значення |
|----------|----------|
| Чип | AT7456E (сумісний з MAX7456) |
| Інтерфейс | SPI, **bit-bang** (4 GPIO: CS/MOSI/CLK/MISO) |
| Вивід | OSD-оверлей символів поверх CVBS-відео |
| Сітка (PAL) | 30 × 16 символів |
| Сітка (NTSC) | 30 × 13 символів |
| Кириличний шрифт | завантажується в character-NVM чипа |

Драйвер спілкується з чипом по регістрах MAX7456 (`VM0`, `DMM`, `DMDI`, …),
самотужки формуючи SPI-кадри GPIO-«смиканням» (`shift_out`/`shift_in`,
`at7456e.cpp:54-89`). Наявність чипа перевіряється echo-тестом регістра `DMAL`
(`present()`, `at7456e.cpp:122`); якщо чип не відповідає — порт вимикається, а
система живе далі (`init()` повертає `false`, `at7456e_port.cpp:55`).

**Кириличний шрифт у NVM.** Гліфи заливаються в character-NVM чипа один раз
(`upload_font`, `at7456e.cpp:208`). Щоб не зношувати NVM повторними записами,
використовується sentinel-guard: якщо шрифт уже присутній (збіг байта за
sentinel-адресою) — заливка пропускається. Мапінг UTF-8 → індекси гліфів NVM
живе у `osd_charmap` (розкладка своя для цього чипа, не спільна з іншими
дисплеями).
