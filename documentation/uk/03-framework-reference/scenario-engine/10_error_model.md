# 10 — Модель помилок

> 📖 **In English:** [documentation/en/03-framework-reference/scenario-engine/10_error_model.md](../../../en/03-framework-reference/scenario-engine/10_error_model.md)

Каталог кодів помилок, які повертає API `Engine` і завантажувач, плюс автомат політики провалів дій. Використовуйте його як довідкову таблицю при обробці `EngineError` у бізнес-модулях або інтерпретації відповідей помилок HTTP API.

## Коди `EngineError`

`enum class EngineError : uint8_t` визначений у `engine_error.h`. Повертається методами API (`load`, `start`, `pause`, `abort`, `unload`, `try_recover`) і завантажувачем (`modr_validate`).

| Код | Викликається | Обробка викликачем |
|---|---|---|
| `OK` (0) | Успіх | Продовжити нормальний потік |
| `INVALID_FILE` | Хибне magic, обрізаний `.modr`, `total_size > MODR_MAX_SIZE`, некоректні структури | Рецепт пошкоджений або хибний формат файла. Перевірити шлях, перегенерувати `.modr` з маніфесту |
| `UNSUPPORTED_VERSION` | `format_version` у заголовку не збігається з `MODR_FORMAT_VERSION` | Рецепт скомпільований старішим/новішим компілятором, ніж прошивка. Перекомпілювати рецепти |
| `CRC_MISMATCH` | CRC32 у хвості не збігається з обчисленим | Файл пошкоджено (bit-flip у файловій системі, помилка передачі). Перезавантажити рецепт |
| `BUFFER_OVERFLOW` | Внутрішній offset+count читав би за межами `total_size` | Структурне пошкодження, виявлене завантажувачем. Трактується як безпечний відкат на зловмисний вхід |
| `UNKNOWN_ACTION` | Хеш запису в `action_pool` відсутній в ActionRegistry | Рецепт посилається на незареєстровану дію. Або друкарська помилка автора рецепта, або потрібний модуль не зареєстрований до ініціалізації рушія |
| `UNKNOWN_CONDITION` | Хеш листа в `cond_pool` відсутній у реєстрі умов І не є композитним (all_of/any_of/not) | Те саме — рецепт посилається на невідому умову |
| `INVALID_TRANSITION` | Хибне enum `kind`, `target_phase` поза діапазоном, `kind=COND` з `cond_pool_idx == NO_OFFSET` | Баг компілятора або пошкоджений рецепт |
| `TOO_MANY_TRACKS` | `track_count` > MAX_TRACKS_PER_SCENARIO (6) | Рецепт оголошує більше паралельних доріжок, ніж підтримує рушій. Переробити рецепт |
| `NAME_TOO_LONG` | Ім'я рецепта або доріжки перевищує бюджет | Використати коротші імена (рецепт ≤ 12 символів, доріжка ≤ 8 символів) |
| `NO_SLOT` | Усі слоти MAX_SEQUENCES зайняті | Вивантажити завершений/провалений сценарій перед завантаженням наступного |
| `NOT_LOADED` | Операція вимагає стану LOADED, слот порожній/активний/термінальний | Перевірити стан через `engine.state(handle)` перед операцією |
| `INVALID_HANDLE` | Handle 0 або > MAX_SEQUENCES, або вказує на порожній слот | Викликач передав застарілий або вигаданий handle |
| `INVALID_TRACK` | Індекс доріжки ≥ `track_count` рецепта в діагностичному акцесорі | Викликач ітерує за межами `track_count(handle)` |
| `PARAM_OUT_OF_RANGE` | (Stage 2) значення override не в [min, max] | Редактор WebUI має валідувати перед відправленням |
| `PARAM_NOT_OVERRIDABLE` | (Stage 2) override спрямований на параметр без прапорця OVERRIDABLE | Автор рецепта позначає конкретні параметри як overridable у маніфесті |
| `RESOURCE_CONTENDED` | Ресурс scenario-scope уже утримується іншим handle | Зачекати, доки сценарій-власник завершиться/звільнить, АБО переробити рецепти, щоб не конфліктували |
| `NVS_ERROR` | Callback persist повернув false (немає даних, провал запису) | Перевірити, що партиція NVS змонтована, callback відновлення налаштований |
| `ABORTED_BY_SAFETY` | (Зарезервовано) спрацював глобальний перехід через safety-умову | Дослідити, чому спрацював fault |

## Коди помилок компілятора (`tools/compile_scenario.py`)

Компілятор видає помилки у форматі `<file>:<line>:<col>: error[<code>]: <message>`. Інструментарій (CI, VSCode) може парсити це форматування через стандартний regex для помилок.

### E01XX — Валідація схеми

Загальні невідповідності JSON-схеми, які ловить jsonschema.

| Код | Тригер | Приклад | Виправлення |
|---|---|---|---|
| E0101 | Загальний провал валідації схеми | Відсутнє обов'язкове поле | Прочитати схему в `scenario_schema.json` для точних вимог |

### E02XX — Семантична валідація

Перевірки посилань і типів, які jsonschema не може виразити.

| Код | Тригер | Виправлення |
|---|---|---|
| E0202 | Хеш дії в `known_actions.json` не збігається з djb2 від імені | Перерахувати хеш, виправити таблицю |
| E0203 | Колізія імен дій у `known_actions.json` | Перейменувати одну з дій |
| E0208 | Дубльоване ім'я фази в межах доріжки або дубльоване ім'я доріжки | Перейменувати |
| E0211 | Вираз умови не є об'єктом з одним ключем | Виправити рецепт — кожна умова — це `{"op": ...}` (один ключ) |
| E0212 | Значення `time_elapsed_ms` не є невід'ємним цілим | Використати 0 або додатне ціле |
| E0213 | Тіло `state_key_changed` без поля `key` | Додати `{"key": "..."}` |
| E0214 | Тіло `time_of_day_eq` без `hh` або `mm` | Додати обидва |
| E0215 | Тіло `all_of` / `any_of` не є непорожнім масивом | Використати `[<cond1>, <cond2>, ...]` |
| E0218 | Вираз умови вкладений глибше за `MAX_CONDITION_DEPTH` (16) | Сплющити умови; об'єднати еквівалентні вирази |
| E0220 | Ім'я дії відсутнє в `known_actions.json` (виклик дії в рецепті) | Додати до known_actions.json або виправити друкарську помилку |
| E0221 | Параметр `type` у `set_state` не в дозволеному наборі (i32/f32/bool) | Використати валідний тип |
| E0222 | Тип значення `value` у `set_state` не збігається з оголошеним `type` | Узгодити тип значення з оголошеним типом |
| E0230 | Невідоме ім'я ContinuousBehavior (Stage 1.5) | Зареєструвати continuous behavior |
| E0240 | `@param:<name>` посилається на невизначений параметр рецепта | Додати параметр у `scenario.params` |
| E0241 | Значення `@param` має тип, неправильний для контексту | Узгодити тип значення override з використанням |

### E03XX — Емісія бінарного формату

Помилки на рівні байтового кодування.

| Код | Тригер | Виправлення |
|---|---|---|
| E0301 | Переповнення пулу рядків (>65535 байт) | Зменшити використання рядків, використати коротші імена |
| E0302 | Кількість записів у пулі дій/умов перевищує 65535 | Переробити рецепт (на практиці трапляється рідко) |

### E04XX — Перехресна валідація

Секція `state` маніфесту має оголошувати кожен дзеркальний ключ, який записує рушій.

| Код | Тригер | Виправлення |
|---|---|---|
| E0401 | Рушій записуватиме ключ `<recipe>.<track>_phase_name`, але він не оголошений у `manifest.state` | Додати відсутній запис стану |
| E0402 | Рушій записуватиме ключ з конкретним типом, але маніфест оголошує інший тип | Виправити тип у маніфесті |
| E0403 | Те саме — strict-режим піднімає дрейф типу до помилки | (Лише --strict) |

### Попередження

| Код | Серйозність | Тригер | Виправлення |
|---|---|---|---|
| W0220 | Warning (--strict → error) | Ім'я дії відсутнє в known_actions.json | Додати реєстрацію |
| W0230 | Warning (--strict → error) | Невідоме посилання на ContinuousBehavior | Зареєструвати або видалити |

## Автомат політики провалів дій

За планом Q12. Дія повертає `ActionStatus`; рушій реагує залежно від контексту.

### Entry actions

| Статус | Поведінка рушія |
|---|---|
| `OK` | Перейти до наступної entry action; після завершення всіх — обчислити переходи |
| `PENDING` | Викликати ту саму дію знову на наступному тіку. Рушій інкрементує `action_pending_ticks`; ескалація після ~100 тіків (1 с при 10 мс) до FAILED_RECOVERABLE — Stage 1.5 (наразі залишається PENDING нескінченно; рецепти мають використовувати `wait_ms` для обмежених затримок) |
| `FAILED_RECOVERABLE` | Пропустити решту entry-дій; одразу перейти до обчислення переходів |
| `FAILED_ABORT` | Доріжка → FAILED. Ресурси phase-scope звільняються. Якщо доріжка має прапорець `main_track`, сценарій теж FAILED |

### Exit actions

| Статус | Поведінка рушія |
|---|---|
| `OK` | Перейти до наступної exit-дії; після завершення всіх застосувати засклеплений перехід |
| `PENDING` | Так само як для entry — відкласти на один тік |
| `FAILED_RECOVERABLE` / `FAILED_ABORT` | Пропустити решту exit-дій; застосувати перехід. Провал логується; не блокує просування рецепта |

### Continuous tick (Stage 1.5+)

| Статус | Поведінка рушія |
|---|---|
| `OK` / `PENDING` | Продовжити continuous behavior |
| `FAILED_RECOVERABLE` | Деактивувати ContinuousBehavior; доріжка лишається в RUNNING |
| `FAILED_ABORT` | Доріжка → FAILED |

### Override через `flags.fail_aborts` для конкретної дії

Дескриптор `modr_action.flags` має біти:
- `MODR_ACTION_FLAG_FAIL_ABORTS` (біт 0): трактувати `FAILED_RECOVERABLE` як `FAILED_ABORT`. Використовується для критичних з точки зору безпеки дій
- `MODR_ACTION_FLAG_FAIL_LOGS_ONLY` (біт 1): пом'якшувати `FAILED_ABORT` до `FAILED_RECOVERABLE`. Використовувати ощадливо

### Діагностичні ключі стану, які рушій записує при провалі

Рушій записує (Stage 1.5; ще не реалізовано, але зарезервовано):
- `recipe_<name>.<track>_last_action_error` (int — код помилки)
- `recipe_<name>.<track>_last_action_name` (string)
- `recipe_<name>.<track>_failure_count` (int — інкрементується щофази)

Автори рецептів включають їх у `manifest.state` для видимості в UI.

## Формат помилок HTTP API

Форма JSON-відповіді при помилці рушія:

```json
{"ok": false, "error": "<engine_error_string>"}
```

`engine_error_string` відповідає stringified-формі enum `EngineError`:
- `ok` (зазвичай не з'являється — успіх повертає `{"ok": true, ...}`)
- `invalid_file`, `unsupported_version`, `crc_mismatch`, `buffer_overflow`
- `unknown_action`, `unknown_condition`, `invalid_transition`
- `too_many_tracks`, `name_too_long`
- `no_slot`, `not_loaded`, `invalid_handle`, `invalid_track`
- `param_out_of_range`, `param_not_overridable`
- `resource_contended`, `nvs_error`, `aborted_by_safety`

HTTP-статус: 400 для помилок рецепта/викликача, 500 для misconfiguration рушія (наприклад, nullptr engine pointer).
