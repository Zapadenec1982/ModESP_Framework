# `ld2410b` — mmWave радар присутності (24 ГГц)

> 📖 **In English:** [documentation/en/03-framework-reference/drivers/ld2410b.md](../../../en/03-framework-reference/drivers/ld2410b.md)

HLK-LD2410B — 24 ГГц mmWave-радар присутності людини. Виявляє **рухомі** і **нерухомі** (статичні) цілі до ~6 м, віддає по UART (256000 8N1) кадри з: станом присутності, дистанцією рухомої/статичної цілі (см) та енергією по гейтах. На відміну від PIR, ловить нерухому людину (сидить/спить).

Драйвер реєструється як `sensor` з `hardware_type: uart_bus`, `requires_address: false`, `multiple_per_bus: true`. **HAL володіє UART-портом** (секція `uart_buses` у board.json) — драйвер лише читає байти й парсить протокол кадрів `F4 F3 F2 F1 … F8 F7 F6 F5`.

ВИМАГАЄ: `driver` (UART) з ESP-IDF, `modesp_hal`.

## Залізо (board.json)

```json
"uart_buses": [
  { "id": "uart_1", "port": 1, "rx": 18, "tx": 17, "baud": 256000 }
]
```

| Поле | Опис |
|---|---|
| `port` | Периферія UART (1/2; **0 — консоль**). |
| `rx` | MCU RX ← TX датчика (**обов'язково** — звідси кадри). |
| `tx` | MCU TX → RX датчика (опційно — лише для команд конфігу, див. нижче). |
| `baud` | 256000 (заводський для LD2410). |

Логіка UART — **3.3 В** навіть при живленні 5 В, тож підключається до ESP32 напряму без level-shifter.

## Прив'язки (bindings.json) та address-канали

Один фізичний датчик віддає кілька величин. Оскільки `read()` повертає одне число, **поле `address` обирає канал** (як ROM у DS18B20). Кілька ролей можуть ділити одну UART-шину (`multiple_per_bus`) — кожна з **унікальним** `address`:

| `address` | Канал | Одиниці |
|---|---|---|
| `presence` (або порожнє) | є ціль (рух+статика) | 0/1 |
| `moving` | дистанція рухомої цілі | см |
| `static` | дистанція статичної цілі | см |
| `detect` | дистанція виявлення | см |
| `moving_energy` | енергія рухомої цілі | 0-100 |
| `static_energy` | енергія статичної цілі | 0-100 |

```json
{"hardware": "uart_1", "driver": "ld2410b", "role": "presence",       "address": "presence", "module": "equipment"},
{"hardware": "uart_1", "driver": "ld2410b", "role": "move_distance",  "address": "moving",   "module": "equipment"},
{"hardware": "uart_1", "driver": "ld2410b", "role": "still_distance", "address": "static",   "module": "equipment"}
```

EquipmentBase публікує кожну роль у `equipment.<role>` (напр. `equipment.presence`, `equipment.move_distance`). Перший binding на порт стає **owner** (читає UART + конфігурує датчик), решта — пасивні «views» на той самий кадр.

## Архітектура читання

```
LD2410B ──UART──▶ Ld2410Port (спільний per-port парсер кадрів)
                      │
        ┌─────────────┼─────────────┐
   presence       move_distance   still_distance   ← Ld2410bDriver (по каналу)
        │             │             │
        └──── equipment.<role> ◀── EquipmentBase (читає read(), публікує)
                      │
              presence-модуль ── presence.detected / presence.state / …
```

## Налаштування датчика (bindings `settings`, build-time)

Owner-instance при init **записує конфіг У датчик** командами LD2410 (`FD FC FB FA … 04 03 02 01`). **Потрібен підключений `tx`** (MCU TX → RX датчика); без нього команди ігноруються, датчик лишається на заводських параметрах (читання все одно працює).

| Ключ | Тип | Деф. | Опис |
|---|---|---|---|
| `absence_s` | int 0-600 c | 1 | «No-one duration» датчика — **швидкість реакції** (заводське ~5 c → повільно). |
| `max_cm` | int 75-600 см | 600 | Нативний gate дистанції (квантовано по 0.75 м). Датчик не детектить далі. |
| `move_sens` | int 0-100 | 0 | Поріг чутливості руху (0 = не чіпати; вище = менш чутливо). |
| `still_sens` | int 0-100 | 0 | Поріг статики (0 = не чіпати; **підняти проти фантомної присутності** від нерухомих об'єктів). |
| `timeout_ms` | int 200-10000 | 2000 | Без кадру довше — `is_healthy()=false` (суто драйверний). |

> ⚠️ Це **статичний config** (застосовується раз при init з bindings.json). У веб-інтерфейс driver-settings НЕ виходять — так влаштований фреймворк (web-настройки = тільки module state-ключі, див. нижче).

## Налаштування з вебу (через presence-модуль, runtime)

Live-керовані налаштування оголошуються як **module state-ключі** в [`modules/presence`](../../../../modules/presence/manifest.json) (`access: readwrite`, `persist: true`) — генератор сам зашиває їх у веб, NVS і MQTT:

| Ключ | Опис | Потребує |
|---|---|---|
| `presence.max_distance` | Софт-фільтр дистанції (cm-точний, крок 10 см) — ігнорувати цілі далі | прив'язані канали `move_distance`/`still_distance` |
| `presence.hold_sec` | Occupancy-утримання після зникнення цілі | — |
| `presence.enabled` | Увімк/вимк детекцію | — |

Це канонічний манифест-driven патерн: дистанцію/утримання крутиш наживо з вебу (модуль гейтить у софті), а глибокий сенсор-конфіг (реакція/чутливість) — build-time у bindings.

## Надає

`{"type": "float"}` — значення каналу публікується в `equipment.<role>`. Для presence-каналу: 0/1; для дистанцій: см; для енергій: 0-100.

## Опційність (Kconfig)

Драйвер **опційний автоматично** — генератор створює toggle у menu **«ModESP Drivers»**:

```
CONFIG_MODESP_DRIVER_LD2410B   (default y)
```

- `idf.py menuconfig` → ModESP Drivers → зніми «ld2410b driver» → код драйвера **не компілюється** (менший бінарник), а `modesp_register_all_drivers()` його пропускає (під `#ifdef`).
- Узгодження з платою: якщо board прив'язує `ld2410b`, але toggle вимкнено — **білд падає з FATAL**. Автоузгодити: `python tools/drivers_sync.py --fix` (увімкнути потрібні) / `--prune` (вимкнути зайві для активної плати).
- Жодних ручних правок Kconfig: `components/modesp_hal/Kconfig` згенерований (НЕ редагувати).

Presence-**модуль** (`modules/presence`) — у `project.json`, тож компілюється завжди (конвенція фреймворку: драйвери опційні через Kconfig, бізнес-модулі — ні). Він легкий і **інертний без прив'язаного драйвера** (`equipment.presence` не публікується → `presence.state = none`).

## Типові проблеми

**Повільна реакція (present тримається ~5-12 c після виходу):** заводська «no-one duration» датчика ~5 c + module `hold_sec`. Постав `absence_s` низько (потрібен TX!) і `presence.hold_sec` = 0-1 у вебі.

**«Постійно present» / фантоми:** датчик ловить нерухомі цілі (меблі/відображення) з високою дефолтною чутливістю. Підніми `still_sens` (напр. 60) у bindings (потрібен TX).

**Фільтр дистанції «не працює»:** (1) `presence.max_distance` = 0 (вимкнено) або (2) не прив'язано distance-канал (`move_distance`/`still_distance`) — модулю нема що порівнювати. Альтернатива без TX — софт-гейт; з TX — нативний `max_cm`.

**HAL показує `0 uart` / binding пропущено:** стара `data`-партиція. board.json копіюється в `data/` на configure → перебілдь так, щоб CMake переконфігурувався (зміна board.json уже в `CMAKE_CONFIGURE_DEPENDS`).
