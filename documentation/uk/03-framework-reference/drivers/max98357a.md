# `max98357a` — I²S Class-D підсилювач (аудіо-вихід)

> 📖 **In English:** [.../en/.../max98357a](../../../en/03-framework-reference/drivers/max98357a.md)

Драйвер аудіо-виходу для MAX98357A — моно Class-D підсилювача з вбудованим I²S
DAC. Надає здатність `audio` через інтерфейс
[`IAudioSink`](../../../../components/modesp_hal/include/modesp/hal/audio_sink.h):
володіє I²S TX-каналом, DMA та піном SD/shutdown (апаратний mute) і робить рівно
одне — переносить готовий 16-бітний моно-PCM на динамік. Кліпи, декодування,
тони й гучність йому невідомі — це робить модуль `player`, який генерує/декодує
PCM і віддає його у `write()`.

**Роль = здатність (R0.1).** Модуль `player` оголошує роль `audio_main` зі
здатністю `capability: "audio"` і ніколи не знає, який драйвер її дає. Сьогодні
це `max98357a` по дроту (I²S); завтра це може бути інший кодек чи майбутній
транспорт — модуль не змінюється. Драйвер реєструється як `audio` з
`hardware_type: i2s_bus`, `transport: wired`, `requires_address: false`.

Аудіо-вихід — **синглтон**: рівно один sink, який керується єдиним playback-таском
усередині `player`. Тому фабрика будує один статичний екземпляр (zero-heap), а всі
методи sink викликаються з того самого таску послідовно — гонок за I²S-канал немає.

ВИМАГАЄ: `modesp_hal`. Драйвер компілюється лише з увімкненим
`CONFIG_MODESP_DRIVER_MAX98357A` (генерований toggle у меню «ModESP Drivers»).

## Здатність і канали

| Атрибут | Значення |
|---------|----------|
| `capability` | `audio` (споживається модулем `player` як `audio_main`) |
| Напрям | вихід (sink) |
| `hardware_type` | `i2s_bus` (дротова I²S-шина з board.json) |
| `transport` | `wired` |
| `requires_address` | `false` (один підсилювач на I²S-шину) |
| `multiple_per_bus` | `false` |

Один запис `i2s_buses` у board.json → один аудіо-вихід. Канали не мультиплексуються
за `address` (на відміну від BLE-датчиків): MAX98357A моно, одна шина = один динамік.
Формат PCM фіксований інтерфейсом: 16-бітний знаковий моно; частота дискретизації
задається `player` при старті потоку (`start(sample_rate_hz)`), за замовчуванням
береться `sample_rate_hz` із board.json.

## Прив'язки

### board.json

I²S-шина оголошується в секції `i2s_buses`. Піни BCLK/WS/DOUT обов'язкові; `sd` —
пін апаратного mute (SD/shutdown), `-1` якщо підсилювач підтягнутий на «увімкнено»
апаратно. `sample_rate_hz` — типова частота (для аларм-тонів достатньо 16000).

```json
"i2s_buses": [
  { "id": "i2s_0", "bclk": 15, "ws": 16, "dout": 7, "sd": 17, "sample_rate_hz": 16000 }
]
```

### bindings.json

Одна прив'язка `hardware` (I²S-шини) до драйвера `max98357a`, роль `audio_main`,
модуль `player`:

```json
[
  { "hardware": "i2s_0", "driver": "max98357a", "role": "audio_main", "module": "player" }
]
```

Роль `audio_main` — власність модуля `player` (R1.2), тому `module` мусить бути
`player`. Мітка ролі транспорту не згадує (R1.3): «Аудіо-вихід», не «I²S-динамік».

## Налаштування

Маніфест не оголошує жодного налаштування прив'язки (`"settings": []`). Уся
конфігурація заліза приходить із запису `i2s_buses` у board.json (піни +
`sample_rate_hz` + пін mute), а не з bindings.json. Драйвер навмисно
мінімалістичний: гучність застосовує `player` програмно (`caps().hw_volume ==
false`), черга/пріоритет/декодування теж живуть у модулі.

## Примітки щодо обладнання

- **Розподіл ролей.** HAL зберігає лише конфіг I²S-шини (піни + частота + пін SD).
  Сам `i2s_chan_handle_t`, DMA-буфери та ввімкнення каналу належать драйверу — HAL
  не залежить від `driver/i2s_std.h`. Драйвер бере ресурс через
  `hal.find_i2s_bus(hardware_id)`.
- **Апаратний mute.** Пін SD керує підсилювачем: HIGH = звук, LOW = вимкнено.
  Драйвер тримає SD LOW у спокої (`init()`/`stop()`) і піднімає його лише на час
  потоку (`start()` знімає mute, `stop()` повертає). Якщо SD підтягнутий апаратно,
  вкажіть `sd: -1` — керування піном пропускається.
- **Master-режим.** Драйвер конфігурує I²S у режимі Philips slot, 16 біт, моно,
  ESP32 як master (генерує BCLK/WS). MCLK не використовується.
- **Деградація без падіння.** Якщо `init()` повертає `false` (немає шини в
  board.json, помилка I²S), аудіо просто вимкнене — система живе далі. Роль
  `audio_main` у `player` позначена `optional: true`.

## Типові помилки

**Немає шини в board.json.** Якщо `hardware` у прив'язці не збігається з жодним
`id` у `i2s_buses`, фабрика логує `no i2s bus '<id>'` і повертає `nullptr` — аудіо
не працює. Звіряйте `hardware` у bindings.json з `id` у board.json.

**Драйвер вимкнено в menuconfig.** Плата прив'язує `max98357a`, але
`CONFIG_MODESP_DRIVER_MAX98357A` вимкнено → білд падає FATAL. Узгодьте:
`python tools/drivers_sync.py --fix`.

**Тиша попри «Грає».** Перевірте пін SD: якщо він фізично не підключений або
підтягнутий на LOW, підсилювач лишається в mute. Для завжди-увімкненого модуля
вкажіть `sd: -1`.
