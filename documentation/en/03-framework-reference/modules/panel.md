# `panel` — LED panel readout module (clock / temperature / humidity)

> 📖 **Українською:** [documentation/uk/03-framework-reference/modules/panel.md](../../../uk/03-framework-reference/modules/panel.md)

The `panel` module owns **what** the iPixel / LED_BLE 64×16 RGB matrix shows. It is a decoupled counterpart of the [`ble_led_panel`](../drivers/ble_led_panel.md) driver: the driver owns the BLE link, power and brightness; the module owns the displayed **content**, pushed through the shared `BlePanel` singleton. A SharedState consumer — it never touches BLE directly.

It rotates **three fields** every ~4 s, each health-gated (`equipment.<role>_ok`), de-duped, and re-evaluated at ~4 Hz:

| Field | Source | Health gate |
|---|---|---|
| Wall CLOCK (`HH:MM`) | SNTP local time | — |
| TEMPERATURE | `equipment.room_temp` | `equipment.room_temp_ok` |
| HUMIDITY | `equipment.room_humid` | `equipment.room_humid_ok` |

(The room temperature/humidity come from the [`ble_xiaomi_th`](../drivers/ble_xiaomi_th.md) sensor via EquipmentBase.)

Module priority is **LOW**. `manifest.json` declares one read-only state key: `panel.text`. `project.json` `modules += "panel"`; `main/CMakeLists` `PRIV_REQUIRES += panel`. The feature lives on git branch `feat/ble-led-panel`.

## Rendering

Each field is rendered via `BlePanel::show_text` using the native iPixel **TEXT frame** — per-character 8×16 glyph blocks plus a CRC32. The font is generated by `tools/gen_osd_font.py --target panel` → `generated/panel_font_data.h`.

```cpp
void show_text(const char* s,
               uint8_t r = 255, uint8_t g = 255, uint8_t b = 255,
               uint8_t anim = 0, uint8_t speed = 0x32, uint8_t rainbow = 0);
```

## Pictograph icons

Icons render inline as ordinary glyphs, addressed by Private-Use bytes:

| Byte | Icon | Byte | Icon |
|---|---|---|---|
| `0x80` | thermometer | `0x83` | bell |
| `0x81` | droplet | `0x84` | wifi |
| `0x82` | person | `0x85` | clock |

Examples: `"[clock]12:34"`, `"[thermo]28.5C"`, `"[drop]50%"`.

## Threshold colours

The text colour is chosen by value:

| Field | Range | Colour |
|---|---|---|
| Temperature | `<18` | blue |
| | `18–27` | green |
| | `>27` | red |
| Humidity | `<30` | orange |
| | `30–60` | green |
| | `>60` | blue |

## Native animation

The `anim` byte drives a hardware effect (HW-confirmed on `LED_BLE_E6C5EBE2`):

| `anim` | Effect | `anim` | Effect |
|---|---|---|---|
| 0 | static | 4 | top → down |
| 1 | scroll right → left | 5 | blink |
| 2 | scroll left → right | 6 | breathe |
| 3 | bottom → up | 7 | drop-in (assembles row-by-row) |

`speed` is `0..100`; `rainbow` is `0..9` (colour-cycle). **Default:** temperature uses `7` (drop-in), the other fields are static.

## Graphics — design history

Richer graphics were explored and dropped. DIY per-pixel drawing is one BLE round-trip per pixel (too slow). Full-frame PNG upload works for static images, but on-device PNG *compression* (ROM miniz) exhausts the free heap (~64 KB) on this device, so it isn't viable. The native TEXT frame — font glyphs + icons + colour + animation — is the chosen, working path for the readout.

## Optionality

The module sits in `project.json` → always compiled. The displayed output appears only when the BLE central / `BlePanel` connect path is available — see [`ble_led_panel`](../drivers/ble_led_panel.md#optionality-kconfig) (`CONFIG_MODESP_BLE_ENABLE` + `CONFIG_MODESP_BLE_CENTRAL`).
