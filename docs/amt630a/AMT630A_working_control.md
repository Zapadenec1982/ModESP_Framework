# AMT630A — Перевірений на залізі контроль (working reference)

> Зафіксовано те, що **реально працює** на платі ZCD-630A-4.3D (стенд `stand_s3`,
> ESP32-S3, I²C SDA=GPIO6 / SCL=GPIO5 @ 100 kHz). На відміну від
> `AMT630A_driver_design.md` (багато ⚠ bench-pending) — тут **лише підтверджене наживо**.
>
> **Головний принцип — «Шлях A, мінімальний дотик»:** внутрішня прошивка AMT630A (8051)
> сама вмикає відеотракт і показує камеру за замовчуванням. Ми **НЕ переініціалізовуємо**
> чіп — лише розблоковуємо реєстри й накладаємо OSD. Будь-яка зачіпка відеобанків
> (0x58/0x59/0x5A) через off→on **руйнує робоче відео** (чорний екран / тест-патерн).

---

## 1. Формат I²C-транзакції

Кожен MCU-банк `Fxxh` = окрема **I²C 7-біт адреса**. Низький байт MCU-адреси = номер регістра.

| Банк | I²C addr | Підсистема | Чіпати? |
|------|:--------:|------------|:-------:|
| `FBxx` | **`0x5B`** | OSD (вікна, BGMAP, FONT, палітра) | ✅ так |
| `FDxx` | `0x58` | Global / PWM-підсвітка / PLL | ⚠ не треба |
| `FExx` | `0x59` | AV-декодер / вибір CVBS-входу | ❌ ламає відео |
| `FFxx` | `0x5A` | Video-process + **FFD2 (display on/off)** | ⚠ лише FFD2 |
| `FCxx` | `0x5C` | LCD/Tcon | ❌ НЕ чіпати |
| `5Fxx` | `0x5F` | vendor unlock/init | ✅ для unlock |

**Запис регістра:** `Wire → addr=банк, payload=[reg, value]` (2 байти).
```
amt_w(0x5B, 0x05, 0x1F)   // FB05 = 0x1F  (увімкнути всі OSD-вікна)
```
**Читання:** `write [reg] (1 байт) → read (1 байт)`.

## 2. Послідовність старту ESP (що робимо і в якому порядку)

Усе — у `Amt630aPort::init()` (`modules/display/src/amt630a_port.cpp`).
Реалізація регістрів — `components/modesp_osd/src/amt630a.cpp`.

1. **`dev_.init()`** — додати I²C device-handle банків, probe на `0x5B` (OSD ACK).
2. **`apply_osd_init()`** — vendor-unlock (0x5F) + увімкнути OSD-вікна (FB05). **БЕЗ відеобанків.**
3. **`set_palette(...)`** — OSD-палітра (банк 0x5B).
4. **`window0_setup(...)`** — геометрія вікна W0.
5. **`upload_font(...)`** — залити RAM-шрифт у FONT RAM.
6. рендер тексту (`osd_print`) при оновленні екрана.

⚠ **НЕ викликаємо** `apply_init_table()` (повний FIZIK init) — він робить off→on відео
й руйнує камеру. **НЕ викликаємо** `set_backlight`, `select_input`, video-параметри.

---

## 3. Розблокування + увімкнення OSD — `apply_osd_init()`

Мінімальний набір. Банк `0x5F` (unlock) + `FB05` (вікна). **Жодного відеобанку.**

```
0x5F 0xAF 0x00     0x5F 0xA1 0x55     0x5F 0xA2 0xAA     0x5F 0xA3 0x03
0x5F 0xA4 0x50     0x5F 0xA5 0x00     0x5F 0xA6 0x53     0x5F 0xAF 0x11
0x5F 0xC6 0x42     0x5F 0xC6 0x00
0x5B 0x05 0x1F                         ← OSD: усі вікна ON (bit0–4)
0x5F 0xBE 0x55     0x5F 0xBA 0x00     0x5F 0xBE 0xAA     ← commit
delay 50 ms
```
Без цього unlock OSD-записи **ігноруються** (видно відео, але меню немає).

---

## 4. Перемикач режимів — `FFD2` (банк `0x5A`, reg `0xD2`) ✅ ЗВОРОТНИЙ

`IO_LCD_forced_blank_color` — єдиний **безпечний, зворотний** контроль «відео vs чорне».

| Значення | Екран | Режим |
|:--------:|-------|-------|
| **`0x4F`** | показ AV + OSD | **відео + меню** (прозоре меню поверх живого відео) |
| **`0x54`** | форсований чорний | **лише меню** (непрозорий чорний фон, відео сховано) |

Перемикання `0x4F ↔ 0x54` працює оборотно й **не глушить** відеотракт (не робить off→on).
Це і є «обидва режими».
```
amt_w(0x5A, 0xD2, 0x4F)   // відео+меню
amt_w(0x5A, 0xD2, 0x54)   // лише меню (чорний)
```

## 5. Рендер OSD (банк `0x5B`)

### 5.1 Розмір символу
```
0x76 = xsiz (ширина, px)     // ModESP: 16
0x77 = ysiz (висота, px)     // ModESP: 20  → ysiz слів на гліф
```

### 5.2 Вікно W0 (`window0_setup`)
```
0x07 = cols (символів)       0x08 = rows (символів)
0x09 = xyloc msb (0x00)
0x0A = xloc (ПІКСЕЛІ!)        0x0B = yloc (ПІКСЕЛІ!)   // ModESP центр: 80, 36 на 480×272
```
> `xloc/yloc` — у **пікселях**, не символах (попри таблицю в design-doc). x<~60 з'їдає overscan.

### 5.3 Увімкнення вікон
```
0x05 = bit0–4 → W0–W4 ON.   0x01 = лише W0,  0x1F = всі,  0x00 = OFF
```

### 5.4 Запис BGMAP (текст) — `osd_print`
```
0x0D = addr msb (9-біт BGMAP)
0x00 = addr lsb           // авто-інкремент при записі 0x01
для кожної клітинки:
  0x0E = tile msb (біти 8–9 коду)
  0x01 = tile lsb         // ЛАТЧ у VRAM + addr++
  0x10 = АТРИБУТ           // ⚠ писати НА КОЖНУ клітинку (lag 1 клітинка інакше)
перенос addr lsb→msb апаратно НЕ робиться — після кратного 0x100 перевиставити 0x0D/0x00.
```

### 5.5 Атрибут (`0x10`)
```
attr = (FG & 7) | ((BG & 7) << 4)
кольори: 0 = ПРОЗОРИЙ (видно відео/фон), 1–6 = палітра, 7 = чорний
ModESP: 0x06 = FG color6 (білий), BG 0 (прозорий) → текст поверх відео
        0x76 = FG білий, BG 7 (чорний, непрозорий)
```

### 5.6 Палітра (`set_palette`, idx 1–6, RGB444 0..0x0F)
```
base = 0x56 + (idx-1)*2
0xbase   = Blue (MSB)            // bit0–3 = B
0xbase+1 = (G<<4) | R (LSB)
```

### 5.7 Завантаження RAM-шрифту (`upload_font`)
Гліф = `ysiz` слів (16×20 → 20 слів). RAM-tile `N` ↔ BGMAP-код `0x1C0 + N`.
```
0x76=16, 0x77=20            // розмір
0x05=0x00                  // вимкнути вікна на час запису, delay 25 ms
0x11 = bitmap_start (lsb)  // межа 1bpp/4bpp, РЕЛЯТИВНА до 0x1C0; ставити = first_tile+count
0x70 = bitmap_start (msb)
на кожне СЛОВО гліфа (addr = ysiz*tile + row):
  0x0F = font addr msb (4 біти)
  0x02 = font addr lsb
  0x04 = data msb   ← писати ПЕРШИМ
  0x03 = data lsb   ← ЛАТЧ останнім
0x05 = маска вікон назад (0x01)
```
- Формат гліфа: ряд = 1 слово, **msb-байт = ліві пікселі, bit7 = крайній лівий**. біт=1 → fg.
- `bitmap_start` релятивний: `0x1C0..0x1C0+bitmap_start` = 1bpp текст.

## 6. Керування зі SharedState / WebUI / MQTT

State-ключі модуля `display` (`modules/display/manifest.json`) → застосовуються в
`DisplayModule::apply_screen_params()`. Запис: WebUI `POST /api/settings {key:val}`,
MQTT `{prefix}/cmd/{key}`, або екранне меню.

| Ключ | Тип | Дія | Стан |
|------|-----|-----|------|
| `display.backdrop` | int (select) | 0/1=Сніг/Синій → `FFD2=0x4F` (відео+OSD); 2=Чорний → `FFD2=0x54` (лише меню) | ✅ працює |
| `display.enabled` | bool | вмк/**вимк екрана** (PWM-підсвітка off) | ✅ працює |
| `display.backlight` | int 0–100 | **PWM-підсвітка** (FD42 пін-режим + FD20/21/28/29 + FD1F) | ✅ працює |
| `display.brightness/contrast/saturation` | int 0–100 | video-декодер FFD4/FFD3/FFD6 (діють на **живе відео**) | ✅ працює (підтверджено) |
| `display.input` | int (AV1/AV2) | FED7→FED8→FEDC | ❌ вимкнено (off→on глушить відео) |

## 7. Підсвітка PWM (банк `0x58`) ✅ — `set_backlight`

Безпечний банк (відео не чіпає). Без `FD42` (пін у PWM-режим) duty не діє!
```
0x42 = 0x03   // FD42: пін P35/P36 → PWM-режим (ОБОВ'ЯЗКОВО, бракувало без apply_init_table)
0x20 = total lsb   0x21 = total msb     // період (total=0x1000)
0x28 = duty lsb    0x29 = duty msb      // high = total*pct/100
0x1F = 0x03                              // PWM enable
```
`display.enabled=false` → `set_backlight(0)` гасить екран; `=true` → відновлює. ✅

## 8. Що НЕ працює (і чому) — вимкнено свідомо

| Функція | Регістри | Симптом | Причина |
|---------|----------|---------|---------|
| **Вибір входу** AV1/AV2 | FED7/FED8/FEDC (0x59) | будь-яке перемикання → **чорний екран** | послідовність робить off→on відеотракту; не відновлюється (потрібен power-cycle). Значення входів — у `findings/02-video-input-select.md`, але enable все одно глушить |
| **No-signal сніг** | FFB0 (0x5A) | при втраті сигналу сніг НЕ з'являється | не вмикаємо (відеобанк, ризик off→on) |
| **`FEDC` backdrop** | FEDC (0x59) | залипає, не зворотний | хибний регістр; замінено на `FFD2` |
| **`apply_init_table` (повний FIZIK init)** | 0x58/0x59/0x5A | руйнує відео (чорний/тест-патерн) | off→on відеотракту перебиває робочий OEM-стан |

**Ключовий висновок:** на цій ревізії будь-який запис у **відео/AV-банки з циклом off→on**
руйнує робоче OEM-відео й **не відновлюється** програмно (тільки апаратний reset живлення).
Безпечно: OSD-банк `0x5B`, vendor-unlock `0x5F`, PWM-банк `0x58` (incl. FD42),
video-параметри `FFD3/FFD4/FFD6`, і зворотний blank `FFD2`. **Уникати:** вибір входу (FED7/8) +
будь-який off→on відеотракту.
