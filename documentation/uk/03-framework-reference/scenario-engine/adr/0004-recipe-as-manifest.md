# ADR-0004: Рецепт = маніфест (з опціональною секцією `scenario`)

> 📖 **In English:** [documentation/en/03-framework-reference/scenario-engine/adr/0004-recipe-as-manifest.md](../../../../en/03-framework-reference/scenario-engine/adr/0004-recipe-as-manifest.md)

**Статус:** заглушка. Повністю буде написано на Кроці 2 (compile_scenario.py) і Кроці 4 (розширення generate_ui.py).

## Стислий виклад рішення

Рецепт не існує як окремий тип файлу. Рецепт — це повноцінний маніфест модуля ModESP з:
- стандартними секціями (state, ui, mqtt) — обробляються наявним `generate_ui.py`;
- новим полем `module_type: "recipe"`;
- новою опціональною секцією `scenario` — обробляється новим інструментом `compile_scenario.py`.

Один файл, два екстрактори. Наявний конвеєр генерації UI не переписується.

## Розглянуті альтернативи

- Окремі файли `recipe.json` поза каталогом `modules/` — відхилено (ламає manifest-driven конвеєр).
- Авторинг рецептів у DSL для досвідчених користувачів (Tasmota Berry, Lua) — відхилено (потребує heap, дрейф семантики).
- Окремий каталог на кожен рецепт із поділом на кілька файлів — відхилено (over-engineering для MVP).

## Наслідки

- Ключі стану та UI-віджети рецепта пре-генеруються наявним конвеєром (безкоштовний UX для кожного рецепта).
- Розширення `generate_ui.py` мінімальне (~30 рядків коду: розпізнавання `module_type: "recipe"`, пропуск прив'язки до C++).
- Рецепти запікаються у прошивку (нова збірка прошивки на кожен новий рецепт — для завантаження через OTA див. Stage 1.5).
- Потрібно збільшити ємність SharedState з 72 до 256 для дзеркальних ключів кількох рецептів.
